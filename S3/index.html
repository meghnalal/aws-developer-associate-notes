    Important

    Bucket names must be globally unique across all AWS accounts

    Encryption

    SSE-S3 - Amazon manages keys (AES-256)

    • Header: x-amz-server-side-encryption: AES256
    • SSE-S3 encrypt each file with different key

    SSE-KMS - AWS Key Management Service

    • Header: x-amz-server-side-encryption: aws:kms

    SSE-C - Customer provided keys

    • You manage keys, AWS manages encryption
    • HTTPS required
    • Key must be provided with every request
    • x-amz-server-side-encryption-customer-algorithm: AES256
    • x-amz-server-side-encryption-customer-key: \<Base64-encoded key>
    • x-amz-server-side-encryption-customer-key-MD5: \<Base64-encoded MD5 hash>

    Client-Side Encryption:

    • Encrypt data before uploading
    • You manage everything user responsability

    Performance

    Multipart Upload:

    • Required for files > 5GB
    • Recommended for files > 100MB
    • Parallel uploads for speed
    • Each part must be at least 5 MB
    • Except the final part (can be smaller)
    • Max parts: 10,000

    S3 Transfer accelerator:

    Uses cloudfront Increase transfer speed by transferring file to AWS edge location
    good for global users
    FILE USA → Edge USA → (straight to Australia) → S3 Australia

    S3 Replication:

    Cross-Region Replication (CRR)

    • Replicate to different region
    • Use: compliance, lower latency, disaster recovery

    Same-Region Replication (SRR)

    • Combine logs or data from multiple S3 buckets into a single bucket within the same region for centralized processing
    • Account-to-account replication
    • Copy data between different AWS accounts in the same region for organizational separation while maintaining low latency
    • Replicate within same region
    • Use: log aggregation, live replication between accounts
    • Like test and dev account

    Important

    After you enable replication only new object replicated Existing one can be replicated with S3 Batch Replication Deletion with version ID not replicable

    STS:

    • On the production account, create an IAM role and specify the development account as a trusted entity.
    • Set the policy that will grant access to S3 for the IAM role created in the production account.
    • Log in to the development account and create a policy that will use STS to assume the IAM role in the production account. Attach the policy to the IAM users.

    Security:

    User Based:

    • IAM policy: what api call is allowed for a specific user

    Resource Based:

    • Bucket Policy - json policy that allows :
    • Access to other account/ services
    • Force encryption on upload
    • Public access bucket

    Object Access Control List:

    • List of Permission that applies to a file

    Bucket Access Control list:

    • A Bucket ACL is a list of permissions that applies to the bucket itself

    GuardDuty: to detect anomalies with ML
    Use Amazon GuardDuty to monitor any malicious activity on data stored in Amazon S3.

    Storage Classes:

    Amazon S3 Standard - General Purpose:

    • Frequently used data
    • Low latency

    Infrequent:
    Amazon S3 Standard-Infrequent Access (IA):

    • Less frequent data
    • But with rapid access
    • Backup Disaster recovery
    • Min 30 days you pay for
    • More costly then One Zone-IA

    Amazon S3 One Zone-Infrequent Access

    • Less frequent data
    • But with rapid access
    • Single AZ so lost with AZ
    • Min 30 days you pay for

    Glacier:
    Amazon S3 Glacier Instant Retrieval:

    • Low cost
    • Archiving
    • Ms retrieval
    • Once a quarter
    • Min storage 90 days

    Amazon S3 Glacier Flexible Retrieval:

    • Low cost
    • Archiving
    • Retrieval Expedited(1-5) Standard(3-5hrs) Bulk(5-12hr) retrieval
    • Min storage 90 days

    Amazon S3 Glacier Deep Archive:

    • Low cost
    • Archiving
    • Retrieval Standard(12 hours) bulk (48hr)
    • Min storage 180 days

    Amazon S3 Intelligent Tiering

    • Moves automatically between tiers
    • No retrieval charges
    • Stays default → in 30 days not usage moves infrequent access tier → 90 days not usage moves archive instant access tier

    Amazon S3 Express One Zone:

    Amazon S3 Express One Zone is the fastest and lowest-latency storage class in Amazon S3, designed for workloads that need microsecond-level latency

    Order moving:
    Standard → StandardIA → Intelligent tiering → One zone-IA → Glacier Instant retrieval →Glacier Flexible retrieval → Glacier Deep Archive

    To keep in mind

    Moving objects can be automated using a Lifecycle Rules

    Transition Actions - move after x days
    Expiration actions - object delete after x days
    Can be used to delete versions of files
